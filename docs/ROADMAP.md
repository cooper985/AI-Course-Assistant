# 开发路线：从原理到可部署应用

版本 v2，2026-09-17。以 [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md) 为架构依据。P1–P6 是阶段；周数是预计预算，未勾选的项目均未验收。

总投入：12 周核心交付 + 4 周缓冲／深化；每天约四小时，每周约 24 小时计划任务，余下时间用于返工、复盘和休息。

## 1. 统一顺序与阶段门槛

| 阶段 | 预计周 | 核心任务 | 必须拿到的成果 | 依赖与实验 |
|---|---|---|---|---|
| P1 原理检索 | 1–2 | 修正边界、NumPy Top-K、稳定 ID、Retriever、20 题小样本 | 真实问题返回有序片段、分数、页码；基础断言与结果文件 | 已有 Loader／Splitter／Embedder；建立基线 |
| P2 最小 RAG | 3 | 一个 LLMClient、RAG、证据预算、引用、无答案和错误状态 | 命令行带引用问答；故障不当作拒答 | P1；E4 先用小样本试跑 |
| P3 存储工程化 | 4 | QdrantStore、持久卷、课程过滤、重复导入、版本与资料状态 | 重启恢复；同向量与 NumPy 对齐；RAG 通过同一 Retriever 使用 Qdrant | P2；E0 迁移验证，重跑 RAG baseline |
| P4 课程检索 | 5–7 | 扩充题集、人工核对章节目录、切分／Metadata 对比，择需重排 | E1、E2 逐题结论，E3 执行结果或暂缓理由 | P3；每组实验固定存储与其他条件 |
| P5 规划编排 | 8–9 | 普通规划函数、结构化输出、检查器，LangGraph 状态／分支／修订／反馈 | 通过、缺输入、失败、到达上限都有正确输出；E5 对照 | P4；目录支持覆盖检查，Retriever 提供证据 |
| P6 Web 交付 | 10–12 | FastAPI、SQLite、Vue、部署、保留集评测、文档 | 在线三页面、数据可恢复、新环境可复现、演示材料 | P5；E4／E5 最终验证及冒烟检查 |

不在第 2 周同时安排向量库迁移。第 4 周接入 Qdrant 后，才进行正式检索优化对比。LangGraph 是必做编排，动态 Agent 是可选增强。

## 2. 各周交付

| 周 | 当周最高优先级 | 应能解释的技术点 |
|---|---|---|
| 1 | 边界校验、Top-K、小 Retriever、5–10 个真实问题 | VectorStore 与 Retriever 的差别 |
| 2 | 约 20 题核对、稳定来源、批量 baseline | Hit、Recall、MRR 和失败分类 |
| 3 | LLM + RAG、引用与资料不足 | 检索正确为什么仍可能答错 |
| 4 | Qdrant 替换应用存储、E0 与重启检查 | 持久化、过滤、精确／近似查询 |
| 5 | 标注章节、扩题、E1 切分 | token 预算与语义边界 |
| 6 | E2 Metadata 机制 | 存字段、编码、过滤不是同一件事 |
| 7 | 代表性错误分析，必要时 E3；冻结一个默认检索配置 | 性能、效果与成本取舍 |
| 8 | 目录与目标输入、计划生成、确定性检查 | 计划格式、预算与知识覆盖边界 |
| 9 | LangGraph 编排、有限修订、反馈与 E5 | state、节点、条件边、停止条件 |
| 10 | FastAPI、SQLite 记录、服务器预检查 | 接口与核心分离，配置与状态 |
| 11 | Vue 三页面、服务部署与真实操作 | Web 到 Retriever 的完整调用链 |
| 12 | 最终题集与异常路径、复现 README、演示 | 可信结论、失败案例、个人贡献 |

## 3. 第四个月与延期策略

第 13–14 周补重复实验与修复薄弱项；第 15 周可做第二课程的小规模迁移；第 16 周复试排练、演示视频与离线备用案例。

若 P1–P3 延期，优先推迟 E3、动态 Agent、第二课程、复杂页面；不跳过错误处理和实验基线。必要时把交付延长至第 16 周，保留 Retriever、Qdrant、LangGraph 固定规划和基本 Web 部署。仍不足时由用户明确重排范围，不静默删除核心目标。

## 4. 验收清单

- [ ] M1／P1：Retriever 完整调用 Embedder + NumPy Store；返回结果有来源和分数，真实样本可复现。
- [ ] M2／P2：RAG 可回答并映射引用；无证据和服务失败分开处理。
- [ ] M3／P3：Qdrant 可重启恢复、按课程过滤；重入库不重复；E0 对照通过。
- [ ] M4／P4：E1、E2 有受控对照、逐题记录、成本与失败分析；不预设提升数字。
- [ ] M5／P5：LangGraph 各分支均有测试，修订上限有效；反馈可调整计划，E5 有结果。
- [ ] M6／P6：网址可演示；资料和计划重启可恢复；部署与实验可按文档复现。

勾选时在 DEVELOPMENT_LOG 记录日期、提交、实际命令与结果；不把时间到期当完成。

## 5. 接下来第一天及首周

第 1 天：1h 画出已有 Document → Loader → Splitter → Embedder → VectorStore 数据流；2h 修正切分步长、加载失败、空数据的契约；1h 做正常／非法／空输入检查并记录。当前不要求先安装 Qdrant。

| 天 | 约四小时任务 | 验收 |
|---|---|---|
| 1 | 上述边界约定和验证 | 无效参数不进入循环，读取失败不会引发二次空值错误 |
| 2 | 理解 Top-K，补返回分数和向量校验 | 有序结果、k 超过数量、空库／坏向量行为明确 |
| 3 | 最小 Retriever，封装问题编码和 store.search | 自然语言查询返回片段、分数、来源 |
| 4 | 真实 PDF 串联，核对约 5–10 个问题 | 确认找到的原文是否真正相关 |
| 5 | 文档／块标识、样例记录格式 | 相同数据版本可定位同一证据 |
| 6 | 批量运行小样本，记录失败与理解 | 不只打印向量维度；保存逐题证据 |
| 7 | 1–2h 复盘，其余缓冲 | 第 2 周扩到约 20 题并建立指标 |

每日先说明模块位置和原理再实现；每个可运行里程碑提醒 git add、git commit，提交前检查差异与敏感文件。
