# AI Course Assistant 项目背景与架构

更新日期：2026-09-17。项目原称 AI Course Agent，统一使用仓库名称 AI Course Assistant；学习规划 Agent 是其中的能力模块。

## 1. 定位与目标

面向大学课程学习，构建可部署到服务器的 Web 应用：用户上传课程资料，获得带证据的课程问答，以及符合目标和时间约束的学习计划。

开发周期为三到四个月，每天约四小时。以理解 RAG、LangGraph 编排、技术取舍和实验方法为重点，最终能在考研复试中解释个人设计、实现和验证过程。

最终交付：

1. 可通过网址访问的 Vue + FastAPI 应用。
2. 可追溯来源的课程 RAG。
3. 基于 LangGraph 的学习规划流程，支持条件分支、约束检查和有限修订。
4. 可复现的评测数据、实验结果和失败案例。
5. 安装部署文档、架构说明及演示材料。

## 2. 第一版范围

| 优先级 | 范围 |
|---|---|
| 必做 | 文本型 PDF 入库、课程范围选择、Top-K 检索、引用原文、证据不足处理 |
| 必做 | 一个学习规划流程：目标、基础、时间预算、资料检索、检查与反馈调整 |
| 必做 | 检索评测、切分／Metadata 实验、规划流程对照、基础测试与部署 |
| 条件扩展 | 重排或混合检索、第二门课程、必要的 OCR、简单练习入口 |
| 本周期暂缓 | 独立错题系统、复杂学生画像、全格式解析、知识图谱、多智能体团队、插件市场、多租户、模型微调 |

先选一门资料可用且熟悉的课程作为主验证场景，再考虑第二门。课程总结可作为基于证据的问答任务，不单独建设复杂模块。反馈先用于用户主动调整计划，不宣称已经具备自动学习诊断能力。

## 3. 当前实现基线

基于主分支代码提交 [8a4f93b](https://github.com/cooper985/AI-Course-Assistant/tree/8a4f93b2e10d8fb0b2f14644492b9933bee78480) 的静态审阅；以下不是本次运行验收结果。

| 模块 | 当前实现 | 尚缺少 |
|---|---|---|
| Document | text、metadata | 稳定文档／块 ID 和原文定位 |
| PDF Loader | pdfplumber 按页提取文本，保存来源和页码 | 错误与空结果约定、解析质量检查 |
| TextSplitter | 固定字符窗口和重叠，复制 metadata | 参数校验、章节／段落策略 |
| Embedder | SentenceTransformers + BAAI/bge-small-zh | 查询编码配置、长度检查、批量编码 |
| VectorStore | NumPy 余弦、内存线性扫描、返回 Top-1 Document | Top-K 与分数、校验、持久化 |
| tests | 打印式模块示例，PDF 到向量的 pipeline | 自动断言、可复现样本、真实检索闭环 |
| 应用层 | app.py 为启动提示 | LLM 问答、LangGraph、FastAPI、Vue、部署 |

后续实际进度以 [开发日志](DEVELOPMENT_LOG.md) 为准；上述表格更新时须同步更新代码基线。

下一步优先处理：切分步长无效可能导致循环不结束；加载失败返回 None 与调用方预期不一致；空块访问；零向量／维度不一致；检索缺少分数和 Top-K。不要先扩展界面掩盖这些问题。

## 4. 目标架构

采用模块化单体，保留已有 src 模块；按功能需要新增文件，避免重写和提前搭建通用框架。

```text
Vue 页面 → FastAPI
             ├─ 资料入库：解析 → 切分 → Metadata → Embedding → 索引
             ├─ 课程问答：查询编码 → Top-K → 证据 → LLM → 回答与引用
             └─ LangGraph 学习规划 → 调用同一套检索与模型能力

独立评测程序 → 调用同一套检索／问答／规划业务函数
持久化 → 原始资料、块与向量、必要的计划记录、实验结果
```

基础 RAG 可以独立调用和评测，不要求所有问答先经过 Agent。FastAPI 负责请求与响应，业务逻辑留在核心模块；Vue 负责呈现，不承担检索决策。

## 5. 技术路线与设计原因

| 技术 | 决策 |
|---|---|
| Python、pdfplumber | 保留，用于文本型 PDF 基线 |
| SentenceTransformers、BGE-small-zh | 保留为当前 Embedding 基线，比较后再决定是否更换 |
| NumPy 检索 | 保留为精确检索 baseline，先理解相似度与 Top-K |
| 持久化／向量库 | 先实现可恢复的向量与元数据；根据规模、过滤、延迟决定是否引入独立向量库 |
| LangGraph | 明确保留，用于学习规划的状态、分支、工具调用和有限修订 |
| LangChain | 按具体组件需要使用，不强制将全部模块改写成框架调用 |
| FastAPI、Vue | 保留，核心链路稳定后接入 |
| Docker | 计划用于可复现的服务器部署，未实现 |

Embedding 让问题和资料片段可进行语义相似度比较，不能保证答案正确。相似度不是事实置信度。RAG 不要求一开始就部署独立向量数据库。

当前余弦计算已除以向量范数，未在 encode 中归一化不等于计算错误。字符数不等于 token 数，应检查模型截断。更换 Embedding 模型或编码策略时重建索引并记录版本，不混用向量。

## 6. LangGraph 学习规划模块

用途：把学习目标转成有资料依据、可检查和可调整的计划。它位于应用业务编排层，复用 RAG，不替代加载、切分或检索模块。

预期流程：

```text
输入目标、基础、时间预算
  → 检查输入是否充分
  → 检索课程结构和资料
  → 生成计划
  → 检查时间、目标覆盖、引用
      ├─ 通过：输出计划
      ├─ 可修复且未到上限：修订后再检查
      └─ 信息不足／达到上限：说明限制或请求补充
用户反馈 → 更新约束 → 重新检查与调整
```

计划状态保存目标、可用时间、课程范围、证据、计划、检查结果、修订次数和用户反馈。具体字段在实现前确定，不在此提前扩展框架。

时间总和、必填字段等尽量使用确定性代码检查；解释性评价可由模型辅助。必须设置最大修订次数、超时和失败出口，不进行无限循环。

先用普通函数理解流程，再由 LangGraph 编排同一套函数。固定步骤属于工作流；只有实现模型在边界内动态选择工具或下一步，才称为相应的 Agent 能力。是否增加动态决策，由对照实验决定。

## 7. 课程结构与研究假设

保留课程结构优化方向，但不预先宣称收益：

- 比较固定窗口与章节／段落边界切分，观察证据召回及上下文成本。
- 来源、页码和块 ID 用于追溯；章节标题可用于编码输入，课程／章节可用于用户指定范围过滤。
- 仅保存 Metadata 不会自动改变检索，也不代表理解知识关系；应分别验证它参与检索的具体机制。
- 难度标签不等于学生掌握程度。先依据用户自报基础，不构建未经验证的学习画像。
- 值得展示的特色是课程结构利用、证据追溯、受约束规划与实证分析，不把常见 RAG 组件宣称为原创算法。

重要模块实现前先写实验目的、baseline、变量、指标和流程，详见 [实验记录](EXPERIMENT_RECORD.md)。

## 8. Yuxi 借鉴边界

学习模块职责划分、统一知识处理、稳定来源标识、状态管理和独立评估；采用适合个人项目的简化实现。

暂不复制其多租户、多存储集群、复杂任务恢复、沙盒和插件生态。这些服务于 Yuxi 的平台规模，当前项目优先保证核心链路与实验。

参考：[Yuxi 架构](https://github.com/xerrors/Yuxi/blob/main/ARCHITECTURE.md)、[LangGraph 工作流与 Agent](https://docs.langchain.com/oss/python/langgraph/workflows-agents)。

## 9. 部署与最终验收

目标是单台服务器上的低并发演示应用：Vue 页面 + FastAPI + 持久数据，生成模型优先调用外部 API，小型 Embedding 模型可在服务器运行。具体硬件根据实测选择，不预先购买 GPU。

验收要求：

- 通过网址完成资料选择／上传、问答引用和学习规划。
- 重启应用后资料与索引仍可恢复。
- 提供配置样例、安装与启动步骤，不提交密钥。
- 配置 HTTPS、基本访问控制、上传限制和调用额度限制。
- 保存关键错误日志，明确失败状态，并测试恢复与重新部署。
- 如允许不同用户上传私人资料，必须隔离访问；第一版也可以采用受控演示账号与公共样本。
- 实验材料可以本地保存，不必建设独立评测网页。

## 10. 本次规划调整记录

| 调整 | 理由与收益 | 成本与复试价值 |
|---|---|---|
| 收敛为问答 + 学习规划 | 三到四个月内保证闭环与验证 | 推迟外围功能，核心可讲清楚 |
| 明确保留 LangGraph，后于 RAG 引入 | 对应状态、分支和有限修订需求 | 增加编排学习，但有具体设计可展示 |
| 细化 Metadata／Agent 对照 | 分清收益来自知识还是流程 | 增加标注和评测成本，提升结论可信度 |
| 增加部署验收 | 最终形成可访问的应用 | 预留交付时间，体现完整工程流程 |

更大的调整必须先说明必要性、收益、成本和复试展示影响，不轻易推翻已有设计。具体任务见 [路线图](ROADMAP.md)。
