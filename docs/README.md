# 项目文档导航

本目录记录 AI Course Assistant 的目标、进度与实验依据。规划更新日期：2026-09-17。

| 文档 | 用途 | 更新时机 |
|---|---|---|
| [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md) | 项目定位、范围、架构、技术选择与当前基线 | 目标或架构发生变化时 |
| [ROADMAP.md](ROADMAP.md) | 12 周核心路线、4 周缓冲、每日任务与验收条件 | 每周复盘后 |
| [DEVELOPMENT_LOG.md](DEVELOPMENT_LOG.md) | 实际开发、验证与问题记录 | 完成一个开发任务后 |
| [EXPERIMENT_RECORD.md](EXPERIMENT_RECORD.md) | 实验设计、配置、结果与结论 | 重要模块实现前及每次实验后 |
| [WEEKLY_REVIEW.md](WEEKLY_REVIEW.md) | 每周总结、方向检查与下一周优先级 | 每周一次 |

## 使用约定

- 项目价值 > 功能数量；技术理解 > 快速实现；可解释性 > 黑盒调用；长期成长 > 短期效果。
- 先说明模块用途、架构位置、与 RAG／Agent／Yuxi 的关系，再实现。
- 区分“代码存在”“已经运行验证”“已通过效果实验”，不混用完成状态。
- 开发日志保留历史；新记录按实际日期追加，不把旧计划自动算作完成。
- 实验没有运行就写“待运行”，不填写推测分数；规划变更不代表功能已经实现。
- 每次重要架构调整记录原因、收益、成本和复试价值。
- 每个可运行里程碑提醒进行 git add、git commit；提交前检查差异、验证结果和敏感文件。
- 周复盘文档不等于定时通知服务，定时提醒需要单独设置。
