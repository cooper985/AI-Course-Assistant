# 新聊天与项目文档入口

规划版本：v2，2026-09-17。这套文档服务于“先理解原理、逐步工程化”的 AI Course Assistant。

## 1. 新聊天先读什么

1. 本文件：阅读顺序与指导约定。
2. [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md)：完整目标、现状、架构、模块职责、技术选择及阶段边界。
3. [DEVELOPMENT_LOG.md](DEVELOPMENT_LOG.md) 的最新记录 + 当前相关源码／测试：确认实际进度。
4. [ROADMAP.md](ROADMAP.md)：确定当前阶段与今天任务。
5. 实现重要模块前读 [EXPERIMENT_RECORD.md](EXPERIMENT_RECORD.md)；每周再读 [WEEKLY_REVIEW.md](WEEKLY_REVIEW.md)。

文档说了“计划”，不能当成实现；新代码优先于旧状态快照。架构与选型以 PROJECT_CONTEXT 为统一依据，时间安排以 ROADMAP 为准。若不一致，说明差异再核对，不自行猜测。

## 2. 聊天指导约定

- 开始指导先确认读取的分支／提交、实际阶段、阻塞及最近完成证据。
- 用自己的话说明模块是什么、为什么需要、在架构哪里、与 RAG／Agent／Yuxi 的关系。
- 给出今天约四小时、最多 1–3 项核心任务及验收标准；一个小步骤一个小步骤推进。
- 先最小实现；解释关键代码、路径、设计原因和边界。不要一口气生成全项目。
- Retriever 必做；NumPy 是原理和精确检索 baseline；Qdrant 是 P3 目标存储；LangGraph 是 P5 规划编排。阶段安排见 ROADMAP。
- 先修正确性和建立评测，再做优化；实验在模块开发过程中同步设计与记录。
- 基础函数用有效边界检查；效果策略用对照实验。不因使用框架就认定存在技术创新。
- 完成可运行里程碑后提醒 git add、git commit，并检查差异、敏感文件与验证证据。
- 完成情况必须来自运行结果或用户反馈，不能以时间过去代替完成。
- 如无法读取 GitHub／本地代码，直接说明缺失文件，请用户提供；不声称已经读过。
- 不创建空壳目录、工厂、插件系统来“预留扩展”；有真实第二实现时再整理公共调用。
- 新建议若改变选型或阶段，先解释必要性、收益、成本、展示影响，并在获准更新时同步文档。
- 周复盘记录不等于自动提醒；定时任务单独配置，不能保证未配置的每日主动通知。

## 3. 可直接发给新聊天的开场请求

> 请按 docs/README.md 的阅读顺序读取项目文档和相关源码，说明你读取的提交、实际已完成模块及当前阶段。请沿“NumPy + Retriever → 最小 RAG → Qdrant → 课程检索实验 → LangGraph → Web 与服务器交付”指导我。今天按约四小时安排任务，先解释原理、模块位置和验收方法，再分步实现；涉及重要策略时先设计实验。不要把规划当成完成，不轻易变更选型，里程碑完成后提醒 Git 版本管理。

## 4. 文档维护分工

| 文档 | 保存什么 | 更新时机 |
|---|---|---|
| PROJECT_CONTEXT | 目标、模块、选型、现状基线 | 架构／范围变化或阶段验收 |
| ROADMAP | 阶段、依赖、工时、下一步 | 周复盘后 |
| DEVELOPMENT_LOG | 实际完成、运行验证、问题 | 每次里程碑后，保留历史 |
| EXPERIMENT_RECORD | 目的、配置、结果与结论 | 重要模块前与实验后 |
| WEEKLY_REVIEW | 偏离检查、优先级和反思 | 每周一次 |

此前对话或早期报告如有“向量库待定”“Retriever 未单列”等表述，以 v2 为准。
