# 实验设计与结果记录

更新日期：2026-09-17。**当前下列实验均为待运行，没有定量结果。**历史模块打印测试不等于效果实验。

## 1. 数据与可复现约定

先建立约 20 题人工核对样本，逐步扩展到 80–120 题，覆盖定义、比较、跨段落、多证据和资料无答案问题。主课程待按资料情况选定。

每题记录问题、课程范围、题型、参考答案要点、原始文档版本、页码、证据文本／区间、是否可回答以及人工核对状态。

- 开发集用于调参；保留测试集只用于最终验证，可参考约 2:1 划分。
- 同义改写和高度重复问题分到同组，尽量按知识点组划分。
- 跨切分方案以原文证据位置或必要事实项为 gold，再映射各方案 chunk；不可直接沿用旧 chunk_id。
- 模型生成题目必须人工核对，不能把自动生成答案视为真值。
- 记录代码提交、资料版本、模型 revision、查询编码、切分、Top-K、提示词、生成参数、硬件、耗时、成本和逐题结果。
- 样本少时报告题数及逐题变化，避免仅用平均分宣称显著收益。

## 2. 指标口径

| 指标 | 约定 |
|---|---|
| Evidence Recall@K | 前 K 个结果覆盖的必要证据项数／该题必要证据总数，先逐题计算再平均 |
| Hit@K | 前 K 个结果是否至少命中一项有效证据；不与多证据召回混用 |
| MRR | 首个有效证据排名的倒数，未命中为 0，再对问题平均 |
| 回答正确性 | 按预先定义的关键事实要点人工评分 |
| 引用支持率 | 被引用原文确实支持的已引用事实陈述数／已引用事实陈述数；另报应引用但未引用的情况 |
| 正确拒答／误拒答 | 分别在无答案题和有答案题上统计；不混为一个比例 |
| 规划约束违反率 | 超过时间预算或违反指定硬约束的任务比例 |
| 成本 | 上下文 token、模型调用次数、耗时、实际费用（可得时） |

无答案题不计算依赖 gold 证据的召回指标；分母为空时记 N/A，并报告有效样本数。证据覆盖匹配规则应在运行前固定并抽样人工复核。

## 3. 预注册实验

实验随开发开展，不等项目做完再补：P1 建立小样本检索基线；P2 开始 E4；P3 做 E0 并复跑问答基线；P4 完成 E1、E2，按需做 E3；P5 开始 E5；P6 用保留集验证最终配置。E0 是工程正确性验证，不作为研究创新。

### E0：NumPy → Qdrant 迁移验证（待运行）

- 目的：确认更换存储没有改变编码、距离度量、范围过滤和引用映射；不假定数据库迁移提高语义质量。
- Baseline：固定向量和 Chunk 的 NumPy 精确余弦 Top-K。
- 变量：仅更换存储后端；Qdrant 先使用所安装版本支持的精确查询配置并记录。
- 控制：同一批向量、查询向量、ID、课程范围、距离度量和 K；两端均在候选范围内检索，不能先全库 Top-K 再过滤。
- 数据：含两个课程、相似文本、同分结果与边界输入的小型固定样例，加 P1 的真实问题。
- 指标：结果 ID 与分数的一致性、过滤越界数、重复入库后的点数、重启后的可检索性；浮点容差和并列结果规则先约定。
- 流程：导入同一向量 → 比较无过滤与课程过滤 → 重复导入 → 重启 → 删除指定文档 → 检查无残留可见证据；另测试中途入库失败不会成为 ready。
- 决策：差异先定位到归一化、度量、过滤、并列排序或映射错误；通过后再作为应用后端。
- 可选：数据量确有需求时，再测近似检索相对精确近邻的召回与延迟；该近邻召回不同于人工标注的 Evidence Recall。

### E1：切分策略（待运行）

- 目的：验证章节／段落边界是否减少课程证据被切断的问题。
- Baseline：现有固定字符窗口，起点 500／50。
- 变量：先小范围调整窗口参数，再比较结构切分；不同时更换模型。
- 控制：相同解析文本、Embedding、查询编码、题集及 Top-K。
- 指标：Evidence Recall@5、MRR、多证据完整性、token 数及耗时。
- 流程：建立基线 → 分析失败 → 加入结构策略 → 开发集选择 → 保留集验证。
- 公平性：补充相近上下文 token 预算比较，结构切分同样限制块长。
- 决策：收益与成本均可接受时才设为默认；保存无收益案例。

### E2：Metadata 机制消融（待运行）

- 目的：分清章节信息通过什么机制影响检索。
- Baseline：来源等 Metadata 仅用于显示。
- 变量：分别比较标题加入编码、用户指定章节过滤、相邻片段补充，一次改变一项。
- 控制：相同切分、模型、数据；改变编码文本时重新建索引。
- 指标：证据召回、过滤漏召回、答案正确性及上下文成本。
- 流程：定义具体机制 → 开发集验证 → 保留集配对分析。
- 限制：不能用 gold 章节替用户选择范围；只保存字段不应改变排名。

### E3：Embedding 或重排（待运行，按失败类型选择）

- 目的：判断瓶颈是否在语义表示或候选排序。
- Baseline：当前 BGE + 余弦检索。
- 变量：最多两个 Embedding 设置，或同一候选集有无 reranker；分别开展。
- 控制：切分、语料、问题与评价口径一致。
- 指标：Recall@5、MRR、查询耗时、索引时间和空间。
- 流程：基线错误分类 → 择一比较 → 分析改善与退化题。
- 决策：解析错误先修解析；没有收益可保留当前方案并结束实验。

### E4：回答、引用与证据不足（待运行）

- 目的：区分检索收益、生成错误和无依据回答。
- Baseline：同一 LLM 不检索；对照固定 RAG。
- 变量：是否提供检索证据；另加人工正确证据条件用于诊断。
- 控制：模型、任务要求、题集、生成参数一致；门控参数在开发集校准。
- 指标：事实正确性、引用支持与遗漏、正确拒答、误拒答、成本。
- 流程：逐题检查答案和原文，模型评分只作辅助并人工复核。

### E5：学习规划与 LangGraph 编排（待运行）

- 目的：验证检查／修订能否改善约束满足，而非只生成更长计划。
- 数据：约 20–30 个目标、基础、时间预算、信息缺失或冲突场景。
- Baseline A：普通 LLM 单次生成。
- 对照 B：RAG + 单次生成。
- 对照 C：相同知识访问能力下的生成—检查—有限修订流程，由 LangGraph 编排。
- 可选 D：实际实现动态工具选择后，再追加受限 Agent。
- 变量：证据访问、检查／修订、动态决策逐层比较；不可将 A 与 D 的差值全归因于 Agent。
- 控制：模型、数据、输入、评分口径一致；记录调用预算，必要时补相近预算对照。
- 指标：时间约束违反率、知识覆盖、引用正确性、人工可执行性评分、失败／超时、token 与延迟。
- 流程：预先定义评分规则，隐藏方案名人工评分，对易波动任务重复运行。
- 边界：评价流程行为，不声称 LangGraph 本身提高模型智力；不能据此证明真实学习效果提升。
